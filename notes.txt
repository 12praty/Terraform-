=============

Terraform Architechture
=======================

terraform init -> terraform fmt -> terraform validate -> terraform plan -> terraform apply ->terraform destroy

==>terraform init --> To Initialize terraform script

==>terraform fmt --> Format terraform script ident spacing ( it will get script in   
	proper order )	

==>terraform validate --> Terraform script syntax will be verified ( validated )

==>terraform plan --> Creates Execution plan for terraform script

==>terraform apply --> Creates actual resources in cloud based on given plan

==>terraform destroy -->  It will destroy / delete the resource which got created in cloud

Ami
------
==>AMI stands for Amazon Machine Image.
	->Think of an AMI as a template/image of a computer that AWS uses to create an EC2 	
		server.
	->Simple example
		->When you buy a new laptop, you need an operating system:
					Laptop
  			  		  ↓
			Install Windows / Linux / macOS
==>With EC2:
					 EC2
                      ↓
                 Choose an AMI
                      ↓
         AWS creates the server using that AMI
==>An AMI can contain things like:
	->Operating system
	->Pre-installed software
	->System configuration
	->Required files
For example:
Amazon Linux 2023 AMI
        ↓
       EC2
        ↓
Amazon Linux 2023 server

Terraform Taint and untaint
===========================
Taint=>you can taint a resource to using teraform taint to mark it as needing to be re created during next terraform apply (means resource need for redeployment).
command=>terraform taint aws_instance.linux.vm

untaint=>using terraform untaint, you can remove the taint from resources so it will not be recreated and will stay the as it is in next apply.
command=>terraform untaint aws_instance.linux.vm


Terraform Module
================
=>A terraform module is a set of Terraform Configuration files in a single 
  directory

=>Single Directory with one or more .tf files can be considered as a module

=>One Root module can have any number of child modules in terraform
	example : Inside one project or module we can create multiple child modules ex2,s3,vpc........


=>Note : We will be running terraform commands from root module and root module 
	will invoke child modules for execution


Lock file in terraform 
=======================

==> The .terraform.lock.hcl file, which is created or updated when you run terraform init ,
contains specific information about the providers used in your configuration. It's a dependency lock file that ensures consistent and reproducible deployments.


Workspace

Environments of the projects
==========================
It refers to the platform that is required to run our app 
( servers, database, storage, network, tools, softwares...)

One Project may contain multiple env
ex: DEV, SIT, UAT, Pre_prod, PROD 

It allows you to manage multiple distinct environments (like development, staging, and production) with the same Terraform configuration code. 
This prevents you from needing to duplicate your entire codebase for each environment.

Terraform workspace commands
================================

$ terraform workspace new dev

Creates and switches to a new workspace.

Example: terraform workspace new dev creates a new workspace named dev and makes it the active one.

==================

$ terraform workspace select prod

Switches to an existing workspace.

Example: terraform workspace select production switches to the production workspace.

===================

$ terraform workspace list

Lists all available workspaces

================

$ terraform workspace show 

Prints the name of the current workspace.


============================

Workspaces are most powerful when combined with variables. You can use a single configuration and change resource attributes (like instance size or database name) by using different variable values for each workspace.

dev.tfvars
instance_type = "t2.micro"


qa.tfvars

instance_type = "t2.medium"


prod.tfvars

instance_type = "t2.large"

=========================
==> main.tf

provider "aws" {
  region = "ap-south-1"
}

variable "instance_type" {
  description = "instance_type of ec2"
}

resource "aws_instance" "linux_vm" {

  ami             = "ami-0d54604676873b4ec"
  instance_type   = var.instance_type
  key_name        = "terraform-kp"
  security_groups = ["default"]
  tags = {
    Name = "Telusko2-Server"
  }
}



$ terraform apply --var-file=qa.tfvars
